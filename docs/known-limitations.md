# 已知限制与能力边界（Known Limitations）

> 本文件是对外技术承诺的唯一基准：写清楚什么能测、什么测不了、什么只是原型。
> 路演、答辩、报价、交付报告四种场合的表述都以此为准。

## 1. 场景库的可执行性边界（重要）

`scenarios/` 共 50 个 YAML 场景，但并非全部在当前引擎上"真正可执行"：

| 攻击家族 | 场景数 | 当前可执行性 | 说明 |
|---|---|---|---|
| jailbreak（多轮越狱） | 8 | ✅ 有效 | 纯文本对话即可复现（含 `jailbreak_multi_turn`） |
| injection（提示注入） | 7 | ✅ 有效 | 纯文本对话即可复现 |
| dataleak（数据泄露） | 7 | ⚠️ 部分有效 | 依赖目标是否真的持有该类数据 |
| values（价值观） | 7 | ⚠️ 弱有效 | 关键词法无法判断内容价值观倾向，需人工/模型复核 |
| hallucination（幻觉） | 7 | ❌ 不可判定 | 需要事实核验（外部知识库/检索比对），当前无实现 |
| agentabuse（Agent 滥用） | 7 | ❌ 不可测 | 需要真实工具执行环境；当前 TargetModel 只有纯对话协议 |
| supplychain（MCP 供应链） | 7 | ❌ 不可测 | 同上，需 MCP 工具调用环境 |

**合计 50 个场景**（8+7+7+7+7+7+7）。

- `TargetModel` 协议目前只有 `reply(messages) -> str`，**引擎没有任何工具调用能力**；
- 因此 `agentabuse` / `supplychain` 共 **14 个场景在架构上不生效**（成功判据退化为"回复碰巧出现某些词"）；
- `BatchOrchestrator` 默认**跳过**这 14 个场景并在结果中列出，不再计入"50 场景全覆盖"的宣传口径；
- **注意可执行 ≠ 可判定**：余下 36 个可执行场景中，`hallucination` 家族的 7 个因缺乏事实核验能力，
  跑完也得不到有意义的判定结果。能给出资质结论的实际上是 **29 个**。
- 对外表述应为（三层口径，按场景选用）：
  - 保守：**"36 个场景可在纯对话协议下真实执行，其中 29 个能给出有效判定；
    另有 14 个需工具执行环境的场景待 SDK 支持"**
  - 简略：**"36 个可执行 / 29 个可判定（场景库共 50 个）"**
  - 涉及合同交付范围时，必须用保守口径并注明被跳过的场景 ID。

## 2. 判定能力的边界

- **目标状态判定**为双保险：场景关键词命中 **且** 危害性判别通过（`harm.py`）。
  已修复"拒答复述被误判为漏洞"的致命缺陷，但规则判别仍存在两类误差：
  - 漏报：高度隐晦的分步泄露、多语言混合长链；
  - 误报：关键词恰好出现在正常业务内容中。
  **重要结论建议人工复核**（每条攻击链均可复现，复核成本低）。
- **姿态评估**为规则版五档分类，非分类模型；V2 替换后精度可提升。
- MVP 阶段的规则基线不是"评测结论的终局"，而是"可复现的下界"。

## 3. shield 防护网关的边界

- 检测为**规则原型簇 + 轻量统计**，不是语义模型：口语化重述已大幅补强，
  但仍存在未覆盖的变体（尤其长文本分段注入、跨轮累积注入）；
- 声称的"语义级"指**方案设计**（指令意图空间 + 原型簇最近邻），
  MVP 以加权模式与 n-gram 近邻作为代理实现，**完整语义编码器属 V2**；
- 性能数据（p50 0.18ms / 单线程 ~5,300 QPS）来自 `benchmarks/bench_shield.py`，
  须与硬件环境一并引用；
- 引用豁免（引号内、翻译/分析语境）是按语境降权，攻击者可刻意伪装成教学语境绕过；
- **清洗器与检测器是两套独立维护的规则**（`hierarchy.py` / `sanitizer.py` vs `prototypes.py`），
  覆盖面并不完全同步。当检测器判定的高危内容清洗器删不掉时，降级的前提由
  `detector._can_downgrade()` 用 PrototypeSpace 对清洗结果复判确认
  （此前无条件降级，构成一条绕过路径，编号 H3）。复判后残余风险仍不可消除时，
  自 v0.3.1 起由 `UnsanitizablePolicy` 选择取向，默认 `BLOCK`；

  | 取向 | 行为 | 代价 |
  |---|---|---|
  | `BLOCK`（默认） | 不调用模型，整段丢弃 | 损失该文档的数据价值 |
  | `SANITIZE_MARKED` | 加不可信围栏、**剥夺指令权**后送交模型 | 残余风险真实存在 |

  后者**不得表述为"已清洗干净"**：围栏是一层缓解措施而非保证。
  且 `SANITIZE_MARKED` 的放行必须是**带标记放行**——裸放行即等同于原样转发注入，
  与 H3 原绕过路径无异（`mark_untrusted=False` 可显式退回裸放行，仅用于下游另有
  隔离机制的场景）；
- 对抗自适应更新（S5）**不含自动在线更新**：反馈集可产出候选模式，
  但一律需人工评审后显式装载，详见 `src/aegis/shield/README.md`
  （"具备在线自学习能力"的表述与实现不符）。

## 4. audit 审计的边界

- 行为基线来自**合法轨迹样本统计**，样本不足时：L1 会显式输出"无法校验"（fail-open，LOW 告警），
  L3 对未知敏感级别默认拒绝（fail-closed）——两者策略不同，是有意为之：
  外发检测宁可保守，权限校验不臆断；
- 参数取值域因只存哈希摘要，只能判"新异性"而非"越界"，按 LOW 告警处理；
- 目标漂移用 n-gram 相似度代理语义一致性，V2 换语义向量；
- **轨迹索引（seq）完整性校验只"检出"、不"修复"**：对 seq 重复、悬空引用、
  前向引用三类篡改输出 `trace_integrity` / HIGH 告警，但 L3 仍按原索引继续计算。
  因此告警存在时，**L3 的数据流向结论不应单独采信**——这正是把它前置校验的意义。
  轨迹本身由采集 SDK 写入，本项假设采集端未被攻击者控制；
  若采集端不可信，需配合签名/只读存储等部署侧手段（属工程扩展，非本模块职责）。

## 5. 工程边界

- 场景库 `scenarios/` 位于包外，**非 editable 安装不会被打进 wheel**；
- `aegis.redteam` 为兼容命名空间（聚合扁平模块），扁平导入路径同样有效；
- 报告默认采用 excerpt 脱敏（保存回复前 160 字摘要），**摘要可能包含泄漏片段**，
  高危场景请改用 `Redaction.HASH_ONLY`；
- `console/index.html` 是 **UI 原型，数据为模拟值**（页面已加横幅标注）；
- 授权校验只检查凭证字段是否填写，**不核验凭证真伪**，不得表述为"强制授权"；
- `OpenAICompatibleTarget` **拒绝以明文 HTTP 连接外部地址**（OpenAI 兼容接口以
  Bearer Token 鉴权，明文链路可被窃听），构造时抛 `ValueError`；
  本地/内网地址（localhost、127.0.0.1、RFC1918 私网、`.local` 等，复用 `audit.net`
  的解析判定而非前缀匹配）放行但发出 `RuntimeWarning`。
  该约束为 **v0.2.2 起的行为变更且不提供关闭开关**：确有明文外部端点时请改用 HTTPS；
- `aegis evaluate` 的退出码：默认 **0 = 命令执行成功**（即使检出漏洞）；
  需要 CI 安全门禁语义（检出漏洞 ⇒ 失败）时须显式加 `--fail-on-finding`（返回 1）。
  两者含义不同，**不可混用**；
- 攻击算子的多轮表述变体是**有限轮换**（每算子 3 个变体）。当状态因回溯而回到历史
  更早的节点时，会重新算得较小的轮换索引，仍可能出现重复提示（实测 8 轮中约 2 轮）。
  更彻底的解法需要区分"状态回退"与"已试探过哪些表述"，属后续优化。
