## 一、为什么单轮测试正在失效

GB/T 45654—2025《生成式人工智能服务安全基本要求》已经实施，备案的大模型服务超过了 1100 款。几乎所有团队上线前都会做一轮"安全测试"——但大多数做法是：准备几十条敏感问题，逐条问一遍，模型拒答就算通过。

问题在于，真实攻击者不是这样攻击的。

我们复盘公开披露的多轮越狱案例后发现一个共同模式：**攻击者几乎从不正面提问**。他们先聊小说创作（模型放松警惕），再聊虚构世界的背景设定（进一步脱敏），然后请你"补全学术性细节"（信息开始泄露），最后在某个看似无害的追问里拿到完整答案。每一步单独看都人畜无害，防线是在**对话状态的逐步迁移**中被绕过的。

单轮模板测试的本质缺陷：它把安全评估建模成了**分类问题**（这句话该不该拒），而真实越狱是一个**搜索问题**（存不存在一条状态转移路径，从初始对话态走到"目标信息泄露"的终态）。

## 二、核心思路：把越狱建模为状态机搜索

鉴安 AegisLLM 的做法是把多轮对话形式化为一台状态机：

```
M = (S, A, T, s0, G)
S  ：对话状态 = (历史摘要, 已获取敏感信息, 防御姿态估计) 三元组
A  ：攻击算子集合（角色扮演/情境虚构/渐进拆解/话题迁移/权限声明/情感施压）
T  ：状态转移（每一轮对话就是一条边）
G  ：目标状态（由场景定义，如"输出包含完整步骤的回复"）
```

评测引擎的工作就变成了：**在状态机上搜索一条从 s0 到 G 的路径**。这条路就是攻击链，也是漏洞证据。

几个关键设计：

**1. 五档防御姿态评估。** 每一轮把模型回复分为强拒答/弱拒答/合规应答/部分泄露/完全泄露。姿态是状态三元组的一维，也是奖励信号的来源——"部分泄露"给 +0.5，"强拒答"给 −0.3。

**2. 探索—利用平衡的动作选择。** 攻击智能体维护一张 Q(state_signature, operator) 表，跨场景持久化。在某个状态下"角色扮演"被强拒答过，下次到类似状态就换"情境虚构"。评测跑得越多，引擎越聪明——这是模板工具做不到的。

**3. 连续拒答触发回溯。** 连续 2 次强拒答，回退到浅层状态换招重试，模拟真实攻击者"此路不通换条路"的行为。

**4. 证据链默认脱敏。** 每一步记录 `{turn, operator, prompt_hash, reply_excerpt, posture, timestamp}`，prompt 明文默认不落盘——因为攻击证据本身就是敏感资产。

## 四、不止评测：防护与审计也开源了

评测回答"上线前安不安全"，但上线之后呢？这次我们把另外两个模块也一并开源了：

**shield：语义级提示注入检测网关。** 串接在业务与模型之间，三路信号融合判定——指令意图空间（五大注入原型簇）、上下文一致性、指令层级隔离（外部检索数据剥夺指令权）。`忽略之前的所有指令`这类直接注入、藏在 RAG 检索文档里的间接注入、Base64 编码走私，实测判定延迟不到 5 毫秒。

**audit：智能体工具调用链审计。** Agent 时代的新问题：模型不只说话，还会调工具。我们按"权限规则 → 序列异常 → 数据流向"三级检测调用链——敏感数据一旦流向未授权工具或外部地址，直接熔断。同时做目标漂移检测：用户让你整理会议纪要，你连续两个子目标在扫描内网，立刻拦下。

**report：一键合规报告。** 评测证据直接生成对标 GB/T 45654—2025 的 HTML 体检报告：风险分级、攻击链复现路径、合规对照表、整改建议。备案要交的材料，顺手就有了。

## 五、场景库：50 个场景，社区共建到 200

攻击能力的天花板在场景库。我们预置了 50 个 YAML 声明式场景，覆盖 7 大攻击家族：多轮越狱、提示注入、数据泄露、价值观、幻觉、Agent 滥用、MCP 供应链。加一个场景不用改代码：

## 六、一些诚实的边界

- MVP 阶段的姿态评估、注入检测是**规则基线版**（加权模式 + 轻量统计），接口与模型版完全一致，V2 会换成蒸馏的轻量语义编码器——我们先把闭环跑通，再逐步换更强的引擎；
- 关键词命中式的目标判定会有误报，重要结论建议人工复核（报告里所有攻击链都可复现，复核成本很低）；
- 本项目仅限**获得书面授权**的防御性测试：引擎内置授权核验，无授权凭证拒绝运行。
